Next 10 prompts to build the pronunciation feature (M5 in PRD.md).

Read PRD.md §4.5b and the "Shadowing" bullet in CLAUDE.md before starting each
prompt — the locked decisions there are non-negotiable. Feed one prompt at a
time; do not batch. Each prompt assumes the previous one landed.

---------------------------------------------------------------------------
PROMPT 1 — Schemas + language→locale mapping (no network yet)
---------------------------------------------------------------------------
Add the pydantic models for the pronunciation feature in backend/app/models/.
Word-level only (PRD §4.5b, MVP scope):
  - PronunciationWord { text: str, accuracy_score: float, status: Literal["correct","mispronounced","omitted","inserted"] }
  - PronunciationResult { overall_score: float, words: list[PronunciationWord] }
Extend the /shadow/analyze response schema so it becomes
  { prosody: ProsodyBlock, pronunciation: PronunciationResult | None }.
Add a Language → Azure locale mapping helper (zh→zh-CN, es→es-ES, en→en-US)
in a small pure module — no HTTP yet. Do NOT accept per-phoneme fields in the
response schema even though Azure returns them; keeping them out prevents the
frontend from depending on them prematurely (see CLAUDE.md "Locked decisions").
Unit-test the locale mapping.

PROMPT 2 — Pronunciation cache module
---------------------------------------------------------------------------
Add pronunciation result caching. Key = sha256(target_cache_key +
learner_audio_hash). Stores <hash>.json ONLY. Learner audio must never touch
disk — hash the in-memory bytes and discard. Either extend services/cache.py
with a second namespace or add a small parallel module; pick whichever keeps
concerns clean. Add pytest coverage for: key stability, key differs when
either input differs, round-trip write/read, no audio files ever appear in
the cache directory. Refer to CLAUDE.md "Caching" locked decision.

---------------------------------------------------------------------------
PROMPT 3 — services/pronunciation.py: Azure REST client
---------------------------------------------------------------------------
Implement backend/app/services/pronunciation.py — pure I/O layer around Azure
Speech Pronunciation Assessment (REST, not the SDK; use httpx.AsyncClient as
required by CLAUDE.md). Signature roughly:
  async def score(audio_bytes: bytes, target_text: str, language: Language,
                  key: str, region: str) -> PronunciationResult
Build the correct URL for the region, set the pronunciation-assessment header
(reference text = target_text, granularity = word, no phoneme output surfaced),
POST the audio, parse the JSON response into PronunciationResult. No language
branching beyond building the locale string. Do not log the key. Do not
persist the audio. On non-2xx, raise a typed error the router can turn into a
clean 4xx/5xx. Unit test with a mocked httpx transport for each of zh/es/en
(verify the correct locale hits the URL/header) and one malformed-response
case.

PROMPT 4 — Wire /shadow/analyze orchestration
---------------------------------------------------------------------------
Update backend/app/routers/shadow.py so a single request returns both blocks:
  1. Run prosody (existing code) unconditionally.
  2. Read X-Azure-Speech-Key and X-Azure-Speech-Region headers. If either is
     missing, return { prosody, pronunciation: null } — do NOT 4xx (see CLAUDE.md
     "Independence" locked decision: prosody must run without Azure).
  3. If both are present, compute learner_audio_hash from the in-memory upload,
     check the pronunciation cache first, else call services/pronunciation.py
     and cache the result. Return both blocks in one response.
Never call Azure when the key is absent (CLAUDE.md security guardrail). Do
not add a second endpoint — keep the frontend to one round-trip. Add router
tests that mock the pronunciation service: key-present path, key-absent path
(pronunciation is null, prosody still populated), cache-hit path (pronunciation
service is not called on the second identical request).

PROMPT 5 — Backend end-to-end tests + failure surfaces
